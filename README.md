# Tubely (ytdlp_frontend)

`ytdlp_api`(あなたのサーバー: `https://yuzu3da.com`)を叩いて、
YouTubeに寄せた見た目で検索・視聴・関連動画・コメントを表示するフロントエンド。

- サイト名は **Tubely**(`SITE_NAME`環境変数で変更可)。YouTube本家と誤認されないよう、
  あえて別名にしています。ロゴなどの商標そのものも使っていません
  (配色・レイアウト・タイポグラフィだけ寄せてあります)
- **ライト/ダークは端末設定と自動連動**(`prefers-color-scheme`。手動トグルはありません)
- **レスポンシブ**: デスクトップ(サイドバー全開)/タブレット(アイコンのみサイドバー)/
  モバイル(サイドバー格納・ハンバーガーで開閉)の3段階でCSSのメディアクエリだけで
  自動的に切り替わります(UA判定はしていません。画面幅ベースの方が確実で壊れにくいため)。
  ハンバーガーボタンはiPad等のタブレット幅でも効くように、画面幅に応じて
  開閉のクラス(`.open`/`.collapsed`)を切り替えるようにしてあります
- **スケルトンローディング**: ページ自体はデータ取得を待たずに即返し、中身はブラウザ側の
  JSが`/proxy/*`を叩いて後から差し込みます。バックエンドが重い/落ちてても最初の画面は
  即座に出ます
- **トップページはこのサイトで実際に見られた動画のランキング**: YouTube公式のトレンド
  スクレイピングが不安定だったため廃止し、`ytdlp_api`側で「このサイト経由で視聴された
  動画」を集計してランキング表示するように変更しました。YouTube本家のトレンドとは
  無関係な、あくまでこのサイト内でのローカルな集計です。誰も何も見ていない最初の状態
  では空になります
- **検索は動画・チャンネル名のみ**(動画ID/URL直接入力欄は廃止しました)
- **登録チャンネル・高評価・視聴履歴**: すべてブラウザのlocalStorageだけで完結する「仮」の
  機能です。実際のYouTubeアカウントには一切反映されません(設定ページに明記してあります)
- **設定ページ**(`/settings`)からAPIサーバーのURLをブラウザ側で上書きできます
  (Cloudflare TunnelでURLが変わった時などに便利)。既定のAPIサーバーURL自体は
  ページ上には表示されません(画面に出したくないという要望に合わせています)
- **動画の実体はサーバー経由で中継**します(`/media/{video_id}?format_id=...`)。
  YouTubeのCDN直リンクはブラウザから直接叩くと再生できないことがある
  (IPアドレスの紐付けが原因と見られる)ため、`ytdlp_api`側で一度取得したバイト列を
  そのまま流す方式にしています。設定画面で隠しているAPIサーバーのURL自体もこれで
  ブラウザから見えずに済みます
- **動画プレイヤーは自前のカスタムコントロール**(再生/一時停止・シークバー・音量スライダー・
  画質選択・全画面表示)です。既定の画質は`itag 18`(360p、YouTubeの定番プログレッシブ
  フォーマット)。他の画質に切り替えても再生位置と再生状態を維持したまま切り替わります。
  全画面表示はiOS Safari(要素単位のFullscreen APIに対応していないことが多い)向けに
  ネイティブの`webkitEnterFullscreen`へのフォールバックも入れてあります
- **高画質(itag 18以外)は映像onlyストリームなので、裏で音声onlyストリームを自動で
  同期再生**します。再生/一時停止/シーク/音量はすべて連動し、1秒おきに0.3秒以上の
  ズレを検知したら自動補正します(完全なフレーム精度の同期ではありませんが、体感で
  気になるレベルのズレは抑えられるはずです)
- **検索結果でライブ配信には赤い「LIVE」バッジ**が表示されます
- **ライブ配信中は動画ページにチャットパネルが出ます**(試験的機能)。継続トークンを
  辿って配信全体を遡る本格的な実装ではなく、取得できた範囲のチャットだけを表示します
- **チャンネルアバター・コメント投稿者のアイコンも表示**します(`ytdlp_api`がbase64で
  返したものをそのまま埋め込み)。動画所有者のアバターは`videoOwnerRenderer`をピンポイントで
  探す方式にしており、コメント投稿者など別人のアイコンを誤って拾わないようにしています。
  チャンネルページの動画一覧に並ぶ各カードのアイコンも、そのチャンネル自身のアバターを
  使い回しているので、個別に取得できずに「?」になることはありません
- **チャンネルページはYouTubeと同じくタブ切り替え式**です(動画/ショート/ライブ/再生リスト)
- **検索結果・チャンネルページは無限スクロール対応**です。下までスクロールすると自動で
  次のページを読み込みます(検索はYouTube本家のcontinuationトークン方式、チャンネルは
  yt-dlpのoffsetベースのページ送り)
- **プレイリストの動画にも、投稿者ごとの個別アイコンを表示**します(プレイリストは
  収録動画の投稿者がバラバラなことがあるため、チャンネルページのようにアイコンを
  使い回さず、動画ごとに実際の投稿チャンネルのアイコンを取得しています)
- **シークバーの再生済み部分は赤色**です(YouTube本家と同じ配色)
- **動画ページに歯車メニュー**を追加(画質/再生速度/字幕/動画情報をまとめて操作可能)。
  以前は画質・字幕・ダウンロードのボタンがコントロールバーに全部並んでいてスマホだと
  画面外にはみ出していましたが、歯車1つに集約したことで解消しています
- **動画を長押しすると2倍速で再生**されます(YouTubeモバイル版と同じ挙動。指を離すと
  元の速度に戻ります)
- **検索窓に入力補完(サジェスト)**を追加しました
- **`/changelog`で更新履歴・バージョンを確認**できます(日付+変更内容のシンプルな形式)
- **サイト全体にログインが必須**です。メールアドレス+パスワードでアカウント作成/ログインし、
  ログインしていない状態でどのページにアクセスしてもログインページへリダイレクトされます。
  ログイン状態は`HttpOnly`・`Secure`なCookieで1週間保持され、期限が切れると自動的に
  ログアウト扱いになります。ログイン/登録ページは柚子(yuzu)をテーマにした専用デザインです
- **チャンネルページのタブは、実際に投稿があるものだけ表示**します(ショート投稿が無い
  チャンネルなら「ショート」タブ自体が出ません)
- **ホーム(自前トレンド)・視聴履歴のチャンネルアイコンも表示**します。視聴時に
  `/api/info`が返すチャンネルアバターを一緒に記録しておくことで、後から一覧表示する時に
  「?」にならないようにしています(履歴はこの変更より前に記録された分は反映されません)
- **プレイリストIDを動画URL(`?v=`)に渡してしまった場合、自動でプレイリストページへ
  誘導します**(YouTubeの動画IDは常に11文字なので、それ以外かつプレイリストIDの
  接頭辞(`PL`/`UU`/`LL`等)に一致する場合はリダイレクトする、という単純な判定です)
- **動画ページのチャンネル情報行と統計(再生回数/高評価/コメント数)を2段に分離**しました。
  以前は1行に詰め込んでいたため、チャンネル登録ボタンの位置が画面幅によってズレたり、
  長いチャンネル名で崩れたりすることがありました
- **設定ページからサーバー側の初期化**ができます(`/settings`)。ブラウザの
  ローカルデータとは別に、`ytdlp_api`側の7時間キャッシュを強制的にリフレッシュしたい時に使えます。
  `ytdlp_api`側で設定した管理者パスワード(`YTDLP_API_ADMIN_PASSWORD`)の入力が必要です
- **動画読み込み中はYouTubeと同じ回転スピナー**を表示します(バッファリング中/読み込み開始時)
- **概要欄はYouTubeと同じく折りたたみ式**です(既定は3行+「もっと見る」、クリックで展開)。
  実際のYouTubeでは視聴者にタグは表示されないため、このアプリでもタグの表示はしていません
- **再生数・登録者数・高評価数は日本語の「万/億」表記**(例: `1980万人`, `91.8万回視聴`)
- **チャンネルページにアバター・バナー画像を表示**します(`ytdlp_api`がbase64で返したものを
  そのまま埋め込むので、画像ホスティング周りの問題を避けられます)
- 絵文字は使わず、全部SVGアイコンで統一しています
- `ytdlp_api`本体とは完全に別プロセス・別ポートで動きます
- Vercel / Render / Railway / Docker対応プラットフォーム、どれでもデプロイできる構成にしてあります

## アーキテクチャ

```
ブラウザ
  │ 1. ページをリクエスト(スケルトン状態のHTMLが即返る)
  ▼
Flask (このリポジトリ)
  │ 2. ブラウザ側のJSが /proxy/xxx を叩く(同一オリジンなのでCORS不要)
  ▼
Flask の /proxy/* ルート
  │ 3. サーバー側からrequestsで ytdlp_api を叩く
  ▼
ytdlp_api (あなたのTermuxサーバー)
```

「バックエンドに繋がらない」場合でも、ページの外枠(ヘッダー・サイドバー・スケルトン)は
必ず表示され、データが載る部分だけ「うまく取得できませんでした」というエラーメッセージに
差し替わります。ページ全体が固まって真っ白、ということは起きません。

## セットアップ(ローカル/Termux)

```bash
cd ytdlp_frontend
python -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

## 起動(ローカル/Termux)

```bash
source venv/bin/activate
python3 app.py
# デフォルトで 0.0.0.0:8000 で待受
```

`ytdlp_api`が別の場所で動いている場合は、環境変数で向き先を変えられます。

```bash
YTDLP_API_BASE_URL=https://yuzu3da.com python3 app.py
```

(何も指定しなければこのURLがデフォルトになっています)

サイト名を変えたい場合:

```bash
SITE_NAME="好きな名前" python3 app.py
```

同じTermux上で`ytdlp_api`(5000番)と`ytdlp_frontend`(8000番)を両方動かす場合は、
`tmux`で2枚窓を開いてそれぞれ起動するのがおすすめです。ngrokで外部公開する場合は
フロントエンド側の8000番をトンネルしてください。

## 「うまく取得できませんでした」が出る場合

これはフロントエンド側の問題ではなく、**`ytdlp_api`(バックエンド)に到達できていない**
状態です。よくある原因は次の3つです。

1. **`ytdlp_api`側の`python3 server.py`が動いていない**
   Termuxのセッションを閉じるとプロセスも終了します。`tmux`や`termux-wake-lock`で
   常時起動させておく必要があります。

2. **ポート開放ができていない**
   DuckDNSなどのダイナミックDNSは「ドメイン名→IPアドレス」の変換をしてくれるだけで、
   ルーターのポート開放(ポートフォワーディング)は別途自分で設定する必要があります。
   ルーターの管理画面で、TCP 5000番をスマホ(サーバー)のローカルIPに転送する設定が
   必要です。

3. **モバイル回線経由だとそもそも直接繋がらないことがある(CGNAT)**
   自宅Wi-Fiではなくモバイル回線でTermuxを動かしている場合、キャリア側のCGNATにより
   外部から直接ポート開放しても繋がらないことがあります。この場合はポート開放という
   アプローチ自体が原理的に無理なので、以前使っていたngrokやcloudflaredのような
   トンネルサービスを使う必要があります。

切り分け方法として、`ytdlp_api`を起動した状態で、**フロントエンドを動かしているのとは
別のネットワーク**から

```bash
curl https://yuzu3da.com/api/health
```

を叩いてみてください。ここが失敗するならフロントエンド側の設定ではなく、
上記のどれかが原因です。

## デプロイ

すべてのデプロイ先で共通して必要なのは環境変数 **`YTDLP_API_BASE_URL`** の設定だけです
(未設定でも `https://yuzu3da.com` がデフォルトなのでそのままでも動きます)。

`ytdlp_api`側(バックエンド)はTermux/自宅サーバーなど常時起動できる環境に置いたままにして、
このフロントエンドだけをVercel/Renderなどにデプロイする想定です。

### Vercel

`app.py`をFlaskのエントリポイントとして自動検出してくれるので、追加設定はほぼ不要です。

```bash
npm i -g vercel
cd ytdlp_frontend
vercel deploy
```

またはGitHubリポジトリをVercelダッシュボードでImportするだけでもOKです。
`vercel.json`で関数のタイムアウトを30秒に伸ばしてあります(yt-dlp経由の情報取得は
多少時間がかかることがあるため)。無料(Hobby)プランではこの上限がさらに短い場合があるので、
タイムアウトが頻発するようならプラン側の制限も確認してください。

静的ファイル(`style.css` / `app.js`)は`public/`ディレクトリに置いてあり、Vercelがここを
自動的にCDN配信してくれます(Flaskの`static_folder`はVercel上では推奨されないため、
あえて`public/`+専用ルートという構成にしてあります)。

### Render

1. GitHubにpushしたリポジトリをRenderで「New Web Service」として作成
2. Build Command: `pip install -r requirements.txt`
3. Start Command: `gunicorn app:app --bind 0.0.0.0:$PORT`
4. 環境変数に `YTDLP_API_BASE_URL` を設定(任意、デフォルトのままでも可)

同梱の `render.yaml` を使えば、Renderの「Blueprint」機能でこの設定を自動反映できます。

### Railway

`railway.json`(と`Procfile`)を同梱しているので、GitHubリポジトリを繋ぐだけでほぼ自動認識されます。
環境変数に`YTDLP_API_BASE_URL`を設定してください(任意、デフォルトのままでも可)。

### Replit

`.replit`と`replit.nix`を同梱しています。Replitでリポジトリをインポートすれば
`pip install -r requirements.txt`のあと自動的に`gunicorn app:app`で起動します。
Secretsタブで`YTDLP_API_BASE_URL`を設定してください。無料プランはスリープすることが
あるので、常時稼働させたい場合は有料プランのAlways On機能が必要です。

### CodeSandbox

`.codesandbox/tasks.json`を同梱しています。GitHubリポジトリをCodeSandboxにインポートすると
自動的に依存関係のインストールと起動タスクが実行されます。環境変数はCodeSandboxの
「Server Control Panel」→「Environment Variables」から設定してください。

### Google Apps Script (GAS) について

**申し訳ないのですが、GASへのデプロイには対応できません。** GASはJavaScript(V8)だけが
動く実行環境で、以下の理由からこのアプリを動かすこと自体が技術的に不可能です。

- このフロントエンド(Flask/Python)もバックエンド(yt-dlpを使うPython製API)も、
  GASのサンドボックスでは実行できません(GASはPythonを実行できません)。
- `yt-dlp`自体がPythonパッケージであり、GAS上で動かす方法はありません。
- GASには「常時起動し続けるWebサーバー」という概念が無く(`doGet`/`doPost`で
  リクエストの都度スクリプトが起動する方式)、今の設計とは根本的に噛み合いません。

もしGAS上で何かを動かしたい場合、`UrlFetchApp`を使って`ytdlp_api`(別途どこかに
立てたもの)を叩くだけの薄いプロキシをGASで新規に書くことは可能ですが、それは
今のコードの「デプロイ」ではなく別物の実装になります。ご要望があれば、
それは別タスクとして着手できます。

### Docker対応プラットフォーム全般(Fly.io / Cloud Run / Azure Container Apps 等)

`Dockerfile` を同梱しているので、コンテナデプロイに対応しているプラットフォームなら
基本的にどこでも動きます。

```bash
docker build -t tubely .
docker run -p 8000:8000 -e YTDLP_API_BASE_URL=https://yuzu3da.com tubely
```

## ページ構成

| パス | 内容 |
|---|---|
| `/` | トップページ。トレンドフィード(グリッド) |
| `/results?q=検索語` | 検索結果グリッド |
| `/watch?v=動画ID` | 動画再生ページ(プレイヤー・チャンネル情報・登録/高評価ボタン・説明文・チャプター・関連動画・コメント) |
| `/channel/{channel_id}` | チャンネルページ(投稿動画一覧・登録ボタン) |
| `/playlist?list=プレイリストID` | プレイリストページ(収録動画一覧) |
| `/subscriptions` | 登録チャンネル一覧(ローカル保存分) |
| `/history` | 視聴履歴(ローカル保存分) |
| `/settings` | APIサーバーURLの変更、サーバー側キャッシュ削除(要パスワード)、ローカルデータの削除 |

## 制限事項

- **トップページのフィードはYouTube公式のトレンドではありません。**
  `ytdlp_api`側で「このサイトを経由して視聴された動画」を集計したローカルなランキングです。
  視聴者数が少ないうちは偏った/空のランキングになります。
- **高画質(映像onlyストリーム)は音声を別要素で同期再生する方式です。** ブラウザの
  `<video>`タグ単体では映像onlyストリームに音声を合成できない(MediaSource Extensionsでの
  自前合成が必要)ため、映像用の`<video>`と音声用の隠し`<audio>`を別々に再生しています。
  ズレの補正は0.5秒おきに3段階で行います: ほぼズレ無し(0.15秒未満)は何もしない、
  小さいズレ(0.15〜1秒)は`playbackRate`をわずかに増減して滑らかに追従(seekしないので
  音が途切れない)、大きくズレた時(1秒以上、バッファリング停止直後など)だけ
  ハードシークで合わせ直します。以前は小さいズレでも毎回ハードシークしていたため
  音がカクカクしていましたが、この変更でかなり滑らかになるはずです。
- **設定ページに「YouTube公式の埋め込みプレイヤー(nocookie)を使う」トグルを追加**しました。
  有効にすると、`youtube-nocookie.com`の公式埋め込みiframeで再生するようになります。
  自作プレイヤー(yt-dlpでの抽出処理、Node.jsでの署名解読)を一切経由しないため、
  抽出周りの不調(bot判定・署名解読失敗等)の影響を受けずに再生だけは確実にできます。
  代わりに画質選択・ダウンロード・10秒スキップ等の自作プレイヤーの機能は使えなくなります。
  抽出自体が失敗した場合でも、このモードが有効なら動画IDだけで再生を試みるフォールバックも
  入れています(動画の詳細情報は出せませんが、再生だけはできることがあります)。
- **動画の左右ダブルタップで10秒スキップ**できるようになりました(YouTube本家と同じ挙動)。
  シングルタップは今まで通り再生/停止、素早く2回同じ側をタップした時だけスキップとして
  扱われます。
- **「高く評価した動画」ページ(`/liked`)を追加**しました。YouTube本家の
  `playlist?list=LL`と同じレイアウト(左にサイドバー情報、右に番号付きリスト)です。
  いいねした際に動画のタイトル・サムネイル等も一緒に保存するようにしたので、
  一覧側で追加のAPI呼び出しをせずに表示できます。**以前のバージョンでいいねした
  古い形式のデータ(タイトル等の情報を持っていない)は、初回アクセス時に自動で
  1回だけリセットされます**(そのままだと一覧表示が壊れて見えるため)。
- **`/history`ページを「このサイトでN回視聴」という視聴回数表示に変更しました。**
  個人アカウントには紐づかない共有の履歴で、動画カードのサブテキストに
  `このサイトでN回視聴`と表示されます(以前の「みんなが見た」といった説明文や、
  「このブラウザの履歴だけ削除」ボタンは撤去しました、シンプルな一覧表示のみです)。
  取得に失敗した場合のみ、このブラウザだけのローカル履歴にフォールバックします。
  併せて、チャンネルアイコン・サムネイルが正しく表示されない不具合も修正しました
  (フロントエンドが`channel_thumbnail`をサーバーに送っていなかったのが原因でした)。
- **「アップデート予告」を画面中央のモーダルで出せるようにしました。** ルート直下の
  `announcement.json`を編集するだけで、コード修正無しに予告を出せます。

  ```json
  {
    "id": "2026-08-10-maintenance",
    "enabled": true,
    "title": "メンテナンスのお知らせ",
    "message": "8/10 深夜にメンテナンスを予定しています。"
  }
  ```

  - `enabled`を`true`にすると表示されます。
  - `id`は「どの予告を見たか」を判定するためのものです。**内容を変えて再度全員に
    見せたい場合は、`id`も別の値に変更してください**(`id`が同じままだと、
    一度閉じた人には二度と表示されません)。
  - 閉じるとブラウザに記録され、同じ`id`の予告は二度と出ません。
- **アップデート通知バナーを追加**しました。`ytdlp_api`側の`changelog.json`を元に
  バージョンを算出し、前回訪問時と違う場合は画面右下に「サイトが更新されました」と
  自動で表示されます(最新の変更点を3件まで表示、8秒で自動的に消えます)。
- **動画ページで`/api/info`を個別に呼ばなくなりました。** `ytdlp_api`側の`/api/stream`が
  info相当の情報も一緒に返すようになったため、動画ページの読み込みは
  `stream`/`related`/`comments`の3リクエストで完結します(以前は`info`も含めて4つ)。
  yt-dlp側の重い抽出処理(Node.jsでの署名解読含む)が動画1本につき2回走っていたのが
  1回になり、体感速度が上がっているはずです。
- **`ytdlp_api`側の`/api/*`アクセス制御に対応しています(要設定)。**
  `ytdlp_api`は表向きのサイト(ちょいツール)で発行したトークンが無いと`/api/*`が
  404になる仕様に変わりましたが、このフロントエンドは専用の合言葉
  (`X-Frontend-Secret`ヘッダー)を送ることでそのチェックを素通りできます。
  **環境変数`YTDLP_API_FRONTEND_SECRET`に、バックエンド側の`frontend_secret.txt`と
  全く同じ値を設定してください。** これを設定しないと、バックエンド側が
  トークン必須化されている場合に検索・動画再生などが軒並み404になります。
- **登録チャンネル・高評価がアカウントに正しく紐づくように修正しました。** 以前は
  サーバーへの「書き込み」だけ同期していて、「読み込み」(一覧ページやボタンの初期状態)が
  ローカルストレージしか見ておらず、実質的に紐づいていませんでした。ページ読み込み時に
  サーバーのデータを取得してローカルへ反映するようにしています。
- **いいねボタンの色がダークモードで変化しにくかった不具合を修正しました。** アクティブ時の
  色をライトモード専用の固定色でハードコードしていたのが原因で、ダークモード用のCSS変数
  (`var(--accent)`)を使うように直しています。
- **お問い合わせをオーナーが削除できるようにしました**(確認ダイアログ付き、一般ユーザーは
  削除できません)。
- **お問い合わせ詳細画面をLINE風の吹き出しUIに作り直しました。** 発言者のアイコン・表示名を
  表示し、オーナーの発言は右寄せ+色付きで表示されます。3秒おきのポーリングで自動更新も
  行います(内容が変わった時だけ再描画するので、チラつきません)。
- **PWA(ホーム画面に追加できるアプリ)対応**にしました。`manifest.json`・Service Worker
  (`sw.js`、CSS/JS/アイコンなどの見た目だけをオフラインキャッシュし、動画・API・ページ本体は
  常に最新を取りに行く設計)・各種アイコンを追加しています。**Service Workerのキャッシュ
  戦略は「ネットワーク優先」に変更しました。** 以前は「キャッシュを即座に返しつつ裏で
  更新」方式だったため、頻繁に更新するこのプロジェクトだと、修正した内容が反映される
  までに1回余分な訪問が必要で、「直したはずのバグがまだ再現する」という混乱の原因に
  なっていました。
- **iOSでダウンロードができない不具合を修正しました。** iOS Safariは`<a download>`属性を
  ほぼ無視するため、`fetch`でBlobとして取得してから保存させる方式に切り替えています。
  あわせて、`ytdlp_frontend`の`/media/`プロキシが`download`パラメータと
  `Content-Disposition`ヘッダーを中継していなかった不具合も修正しました。
- **ファビコンを追加**しました。YouTube本家のロゴをそのまま使うと商標的に問題があるため、
  既存のヘッダーロゴ(赤い角丸四角+白い再生ボタン)と同じデザインの独自アイコンです。
- **サイドバー最下部に、控えめな文字サイズで累計閲覧数を表示**するようにしました
  (バックエンド側でSQLiteのカウンターを持っているだけの簡易的なもので、YouTube本家の
  再生回数のような重複排除はしていません)。
- **ホーム画面のトレンドが外部ソースに切り替わりました。** 急上昇/音楽/ゲームの
  カテゴリタブで切り替えられ、「N分前に更新」の表示も出ます(`ytdlp_api`側が
  1時間キャッシュしている外部データの最終更新時刻を表示しているだけで、この
  フロントエンド自体が何かを定期実行しているわけではありません)。
- **動画/音声はCDN直リンクのみを使います(サーバー経由のプロキシへの自動フォールバックは廃止)。**
  以前は直リンクが失敗した時だけ`/media/...`経由のプロキシに切り替える方式でしたが、
  画質を変えるたびに毎回「直リンクの失敗を待つ」オーバーヘッドが乗って重く感じられて
  いたため、シンプルに直リンクだけを使う方式に変更しました。IPバインドの都合で直リンクが
  そもそも通らない環境では動画が再生できない可能性があります(`/api/proxy-stream`自体は
  バックエンド側に残っているので、必要ならフロント側で再度使う形に戻すこともできます)。
- **動画ページに共有ボタンを追加**しました。対応端末(主にスマホ)ではOS標準の共有シートが、
  非対応環境ではURLをクリップボードにコピーする動作になります。
- **Vercelの無料(Hobby)プランでホストしている場合、動画再生に影響する重要な制限があります。**
  Vercelのサーバーレス関数は実行時間に上限があり、無料プランでは**10秒**で強制終了されます
  (`vercel.json`で`maxDuration: 30`を指定していても、無料プランではこの上限が優先されて
  実質10秒のままになります)。360pのような小さいファイルは10秒以内に収まりやすい一方、
  高画質(特に映像+音声を2本同時に流す場合)は10秒を超えて処理が打ち切られ、再生が
  止まる/始まらないことがあります。**高画質を安定して再生したい場合は、実行時間制限の
  無いRender/Railway/Dockerなどのホスティングに切り替えることを強くおすすめします**
  (デプロイ手順は上記参照。これらは常駐サーバーとして動くため、この制限を受けません)。
- **ライブチャットは試験的な機能です。** 継続トークンを辿って配信全体を遡る本格実装では
  なく、取得できた範囲のチャットだけを表示します。ライブ配信でない動画では表示されません。
- チャンネルの登録者数・コメントなど、値が無い/取得できない項目は単純に非表示になります。
- **登録チャンネル・高評価・視聴履歴はこのブラウザのlocalStorageだけの「仮」の機能です。**
  別の端末/ブラウザからは見えませんし、実際のYouTubeにも一切反映されません。
- **`/settings`のAPIサーバーURL上書きには認証がありません。** デプロイ先を公開すると、
  誰でもこの設定画面から`/proxy/*`の向き先を(自分のブラウザの範囲で)変更できてしまいます。
  個人利用のツールという前提での簡易実装です。他人に公開URLを教える場合は留意してください。
